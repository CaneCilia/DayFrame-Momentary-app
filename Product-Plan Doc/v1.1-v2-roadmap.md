# DayFrame — V1.1 & V2 Engineering Roadmap

With the core MVP (Local-first capture, timeline, and basic UI) completed, we now move into stabilizing cloud features (V1.1) and building out the core user retention mechanics (V2).

---

## 🟢 V1.1 — Cloud & Backup (Focus: Reliability & Trust)
*Objective: Give the user complete confidence that their data is safe, synced, and under their control.*

### Phase 1: Authentication & Identity
- **Sign In / Create Account Screen**: 
  - Build a beautiful, trustworthy Auth screen.
  - Integrate `@supabase/supabase-js` for Email/Password and OAuth (Google/Apple).
  - Update `AuthContext` to persist the session and route the user securely.

### Phase 2: Sync Transparency
- **Cloud Sync Status UI**:
  - Add a subtle status indicator (e.g., a small cloud icon) on the Home Screen and Settings.
  - States: `Synced`, `Syncing...`, `Offline (Pending)`.
  - Build a dedicated "Sync Queue" debug view in Settings to see pending uploads.

### Phase 3: True Google Drive Integration
- **Google Drive Backup**:
  - Replace the current stub in `driveBackup.ts`.
  - Integrate `@react-native-google-signin/google-signin` for OAuth scopes.
  - Implement the Google Drive REST API to silently push photos into a specific `/DayFrame` folder on the user's personal drive.
  - Add a toggle in Settings to Enable/Disable Drive Backup.

### Phase 4: Storage Management & Privacy
- **Storage & Data Settings**:
  - Calculate local SQLite size and image cache size.
  - Add "Clear Local Cache" button (which deletes local photos *only* if `sync_status === 'SYNCED'`).
- **Privacy Hub**:
  - Add a screen explaining the local-first architecture (e.g., "Your photos live on your device first").
  - Provide a button to "Request Account Deletion" (required by App Store/Play Store).

---

## 🔵 V2 — The "Memory Product" (Focus: Nostalgia & Discovery)
*Objective: Transform the app from a daily utility into a product people love looking back at.*

### Phase 5: Advanced Navigation & Viewing
- **Monthly Memories**:
  - Refactor `TimelineScreen` to inject sticky headers for each Month (e.g., "September 2026").
  - Create a "Month Summary" card at the top of each month block.
- **Yearly Timeline**:
  - Add a fast-scroll scrubber on the right side of the Timeline to jump between years quickly.

### Phase 6: Discovery Features
- **On This Day**:
  - Update `HomeScreen` to query the database for memories where `month` and `day` match today, but `year < currentYear`.
  - Display a beautiful "1 Year Ago Today" card above the capture button.
- **Search Engine**:
  - Add a SQLite Full-Text Search (FTS5) virtual table for `memories(caption, date)`.
  - Build a dedicated Search screen with real-time filtering.

### Phase 7: Delight & Sharing
- **Yearly Recap**:
  - Build a specialized horizontal-scrolling "Story" UI (similar to Instagram Stories/Spotify Wrapped).
  - Automatically curate the user's best 12 photos (one from each month).
- **Export / Share**:
  - Implement `expo-sharing` and `react-native-view-shot`.
  - Allow users to export a stylized "Polaroid" version of their memory with the date printed on the bottom to share to Instagram/Messages.

---

### Technical Prerequisites for V1.1
Before writing code for V1.1, we must:
1. Setup the production Supabase Project (Database schema & Storage buckets).
2. Configure Google Cloud Console for Drive API credentials.
3. Switch testing from *Expo Go* to *EAS Development Builds* so we can compile the native Google Sign-In and Notification modules.
